# 04-verify 验证段（待建）

嵌入式与硬件强耦合，无纯软件模拟，验证依赖工程师线下抓取的 artifact。

正常流程：`verify` 之后直接进 `code-review`（05 评审段），`log-analyze` 不入正常流程。

对硬件强耦合的模块，推荐走「测 → 抓取 → log-analyze 分析 → 修复 → 复测」闭环，但**不是每个模块都需要抓 log**——纯逻辑 / 算法类只走 `verify`（静态 + 单测）即可。

计划 skill：
- **`verify`**：可在机器上跑的部分——静态检查 + 单元测试，并调用 `measure` 检查 bootloader / app / 配置区等功能分区是否越界。开始前先询问工程师是否调用 `senior-en` 对代码做设计层面评审。
- **`log-analyze`**：**随时调用、不入正常流程**，主要用于验证代码逻辑、查找 bug。离线分析工程师抓取的报文 / 波形 / 日志。强制拷问：① log 放置方式 ② 各文件夹内容 ③ 分析 / 验证什么功能 ④ 找什么 bug ⑤ 反向出「抓取清单」（抓哪些信号、什么触发、什么采样率），工程师照单抓回后 agent 分析。
- **`hw-test`**：实机 / 硬件在环验证流程，引导工程师线下测并产出可分析 artifact。
